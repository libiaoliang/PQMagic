# PQMagic Project Notes

## Project Overview

PQMagic is a C11 post-quantum cryptography library. The open-source tree builds
the `std` version only. It includes KEM algorithms, signature algorithms, SM3,
Keccak/FIPS202, and shared utility code.

Main areas:

- `include/`: public API and shared configuration headers.
- `kem/`: KEM implementations: `ml_kem`, `kyber`, and `aigis-enc`.
- `sig/`: signature implementations: `ml_dsa`, `dilithium`, `aigis-sig`,
  `slh_dsa`, and `sphincs-a`.
- `hash/`: SM3 and Keccak/FIPS202 implementations.
- `utils/`: random byte generation, cycle counters, and benchmark printing.
- `figure/`: benchmark images used by the README files.

The main public header is `include/pqmagic_api.h`. It exposes per-algorithm
byte constants plus `pqmagic_*_std_*` keypair, encapsulation, decapsulation,
signing, and verification functions.

## Build System

Convenience build script:

```bash
./build.sh
./build.sh --release --build-dir build-release
./build.sh --target pqmagic_static_target
```

`build.sh` defaults to a clean Debug build in `build-debug/`, and only builds
the PQMagic libraries. It removes the old build directory before compiling,
then disables test and benchmark executables. Use `--no-clean` only when an
incremental build is wanted.

Convenience test script:

```bash
./test.sh
./test.sh --smoke
./test.sh --filter ml_kem
./test.sh --list
```

`test.sh` defaults to a clean Debug test build, skips benchmark executables, and
runs every generated `test_*` program. Use `--smoke` for a small representative
set and `--no-clean` only when an incremental test build is wanted.

Primary build path:

```bash
cmake -S . -B build
cmake --build build
```

Useful CMake options:

- `PQMAGIC_VERSION=std` is the only supported open-source version.
- `USE_SM3=ON` is the default hash component for most algorithms.
- `USE_SHAKE=ON` disables `USE_SM3` and selects SHAKE where supported.
- `ENABLE_TEST=ON` and `ENABLE_BENCH=ON` are enabled by default.
- Algorithm toggles: `ENABLE_ML_KEM`, `ENABLE_KYBER`, `ENABLE_AIGIS_ENC`,
  `ENABLE_ML_DSA`, `ENABLE_DILITHIUM`, `ENABLE_AIGIS_SIG`, `ENABLE_SLH_DSA`,
  and `ENABLE_SPHINCS_A`.
- Mode lists include `ML_KEM_MODES`, `KYBER_MODES`, `AIGIS_ENC_MODES`,
  `ML_DSA_MODES`, `DILITHIUM_MODES`, `AIGIS_SIG_MODES`, `SLH_DSA_MODES`,
  and `SPHINCS_A_MODES`.

For a quick build smoke test without compiling every algorithm:

```bash
cmake -S . -B build \
  -DENABLE_KYBER=OFF \
  -DENABLE_AIGIS_ENC=OFF \
  -DENABLE_DILITHIUM=OFF \
  -DENABLE_ML_DSA=OFF \
  -DENABLE_AIGIS_SIG=OFF \
  -DENABLE_SLH_DSA=OFF \
  -DENABLE_SPHINCS_A=OFF \
  -DENABLE_TEST=OFF \
  -DENABLE_BENCH=OFF
cmake --build build --target pqmagic_static_target -j2
```

This was verified in this workspace and produced `build/libpqmagic_std.a`.

Per-algorithm Makefiles also exist under each `*/std/` directory. For example:

```bash
cd kem/ml_kem/std
make all
```

Those Makefiles build local test, speed, and shared-library targets. They use
`PROJECT_HOME=../../..` and include project headers directly.

## Outputs

Top-level CMake builds combined libraries:

- Shared target: `pqmagic_target`, output name `libpqmagic_std.so` on Linux.
- Static target: `pqmagic_static_target`, output name `libpqmagic_std.a` on
  Linux.

When tests and benchmarks are enabled, CMake creates executables in `build/`,
with names like `test_ml_kem_512`, `bench_ml_kem_512`,
`test_ml_dsa_44`, and `bench_ml_dsa_44`.

There is no `ctest` integration in the current tree; test binaries are regular
executables generated by the build.

## Implementation Notes

- Top-level CMake compiles each enabled algorithm/mode into object libraries and
  combines them into the unified `pqmagic_*` libraries.
- `COMPILE_COMPONENT_LIBRARY=ON` additionally builds per-algorithm component
  libraries.
- `utils/randombytes.c` uses `CryptGenRandom` on Windows, Linux `getrandom`
  when available, and `/dev/urandom` as a fallback.
- `SLH_DSA_MODES` and `SPHINCS_A_MODES` encode their hash mode in the mode name;
  the global `USE_SM3`/`USE_SHAKE` selector does not control those two families.
- The repository ignores `build*`, `tmp`, and `TARGET_STATIC_LIBS_SUFFIX`.

## Editing Guidance

- Prefer following the existing per-family layout: `api.h`, `params.h`,
  algorithm sources, `CMakeLists.txt`, `Makefile`, and `test/`.
- Keep public API changes synchronized with `include/pqmagic_api.h` and the
  relevant algorithm-local `api.h`.
- If adding a new mode, update the mode list in top-level `CMakeLists.txt`, the
  algorithm parameter headers, test/bench target generation, and public byte
  constants.
- Be careful with generated build files and install rules. `make install` or
  `cmake --install build` defaults to `/usr/local` unless
  `CMAKE_INSTALL_PREFIX` is set.
- For build validation, start with a narrow algorithm set before compiling the
  full default matrix.
